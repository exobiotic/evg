⚙️ Game Lifecycle POST /api/game
Action (body)EffectRequires
"new"Create a new game — picks 2 players at random from the player pool, loads a map (random or fixed, see Map Selection below), places units. In tournament mode this call becomes a no-op after all unique player pairs have played.≥ 2 players registered
"start"Start the game loop — units begin acting every ActionDelay msGame created first
Both calls return 200 OK with empty body. Send Content-Type: application/json. If tournament pairings are complete, "new" still returns 200 but does not create another match.
🏆 Tournament Mode
BehaviorDetails
Default schedulingThe engine tracks completed pairings and stops creating new games once every unique player-vs-player pairing has happened N times (configurable via rematchCount).
Completion ruleTotal required matches = n * (n - 1) / 2 * rematchCount, where n is number of registered players.
When completeA tournament-complete signal is raised internally and future POST /api/game with body "new" becomes a no-op.
Reset endpointPOST /api/admin/tournament-reset clears pairing history and sets tournament back to incomplete state.
ConfigurationSet rematchCount in PUT /api/admin/game-config to change how many times each pair must play (default: 1).
// Reset tournament progress POST /api/admin/tournament-reset
Useful during testing: change rematchCount to make shorter tournaments (rematchCount=1) or longer ones (rematchCount=3 means each pair plays 3 times before tournament ends).
🔧 Game Config PUT /api/admin/game-config
FieldTypeDefaultDescription
actionDelayint400 msDelay between unit actions in milliseconds
gameValueint1Score points awarded to winner per game
playerTimeoutfloat1.0 sMax seconds to wait for player HTTP response before skipping turn
forceMoveboolfalseUnits lose 1 HP when forced off the map edge
bloodLustboolfalseUnits must attack if an enemy is adjacent
fogboolfalsePlayers only see units within line-of-sight
randomOrderboolfalseRandomise unit turn order each round
staticOrderboolfalseLock unit turn order to initial spawn order
mapWidthint10Battle map width in tiles
mapHeightint10Battle map height in tiles
rematchCountint1Number of times each player pair must play before tournament is complete
fixedMapstringnullName of a specific map to use every game (e.g. "my_map"). Must match a file in wwwroot/assets/maps/
randomMapbool—Set to true to clear any fixed map and return to random selection

All fields are optional — only send what you want to change. Takes effect on the next game created.

// Pin a specific map for every game PUT /api/admin/game-config { "fixedMap": "my_map" } // Switch back to random maps PUT /api/admin/game-config { "randomMap": true } // 3 rematches per pairing PUT /api/admin/game-config { "rematchCount": 3 }

🗺️ Map Management
MethodEndpointDescription
GET/api/maps/listReturns {"maps":[...]} — names of all available map descriptor files
GET/api/maps/load/{name}Load and return a named map descriptor JSON
POST/api/maps/generateGenerate a random map in memory (not saved) — returns map descriptor JSON
POST/api/maps/generate-and-saveGenerate a random map and save it to wwwroot/assets/maps/
POST/api/maps/save-editor-mapSave a hand-drawn map from the map editor (descriptor + tilemap JSON)
// Generate body (all fields optional — shown with defaults) { "name": "Generated Map", "width": 15, "height": 15, "walkableTiles": [11], "nonWalkableTiles":[1,2,3,10,12,19,20,21], "numUnits": 6, "unitTypes": ["dwarf", "minotaur"] }
Maps are stored in wwwroot/assets/maps/. Each map has a top-level <name>.json descriptor and a subfolder with the tilemap grid JSON and tileset PNG. Use the Map Editor at /map-editor.html or the Map Generator at /map-generator.html to create maps visually.
🔍 Query Endpoints
MethodEndpointReturns

All endpoints run on http://localhost:5000 by default (http). HTTPS on port 5001.
💻 Quick Reference — curl / PowerShell
