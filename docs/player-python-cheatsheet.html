EvG Python Player Integration

Complete Guide to Building Python AI Players for EvG Game Server

Quick Setup

Prerequisites

  • Python 3.6 or higher
  • Tornado web framework (pip install tornado)
  • EvG game server running (Docker or local .NET 8 instance)

Installation

Clone or download the evg-python folder from your EvG project:

git clone https://github.com/yourorg/evg.git
cd evg/evg-python
pip install tornado
python main.py

Your Python player server will start listening on port 9080 (or your configured port) and automatically register with the EvG game server.

Note: The main.py uses file monitoring to auto-reload your player.py changes without restarting the server.

Architecture Overview

Your Python player integrates with EvG through a simple HTTP callback model:

  1. Registration: Your Python server calls POST /api/players on the EvG server with your player info
  2. Game Loop: During each unit turn, EvG sends POST http://your-bot:port/ with game state (JSON)
  3. Decision: Your get_actions() function analyzes the game state and returns a list of Action objects
  4. Response: Actions are serialized to JSON and sent back to EvG (under 1 second timeout)
  5. Game End: EvG calls POST http://your-bot:port/end when the game finishes

Key Components

File Purpose
player.py Your AI logic: get_actions(), get_player_info(), game_end()
main.py HTTP server (Tornado), handles incoming requests, file monitoring, registration
game.py Helper classes: GameState, Unit, Action, utility functions

Game State & Data Models

GameState Class

Provided in game.py, represents the complete game state at your unit's turn:

GameState Properties
state.unit        # Your unit (Unit object)
state.units       # Your other units (list of Unit objects)
state.foes        # Enemy units (list of Unit objects)
state.floor_map   # 2D map layout: True = walkable, False = wall
state.empty_map   # 2D map with unit positions: True = empty, False = occupied

Unit Class

Represents a single unit with position, health, and power:

Unit Properties
unit.id       # Unique identifier (string, GUID)
unit.x        # X coordinate (int)
unit.y        # Y coordinate (int)
unit.health   # Current health (int, default 9)
unit.power    # Attack damage (int, default 3)

Unit Methods

Unit Helper Methods
# Get distance from unit to target position (uses cached distance map)
distance = unit.get_distance(target_x, target_y, state)

# Returns None if position is unreachable, otherwise integer distance

Action Class

Represents a single unit action (move or attack in a direction):

Creating Actions
from game import Action

# Move action
action = Action("Move", "Up")      # Directions: "Up", "Down", "Left", "Right"

# Attack action
action = Action("Attack", "Right")

# JSON serialization (automatic)
# {"actionType": "Move", "direction": "Up"}
Note: Each unit can perform at most 2 actions per turn (one move + one attack), but your get_actions() function should return only 1 action. For multiple units, you return a list.

Implementing Your Player

Required Functions (player.py)

You must implement three functions in player.py:

1. get_player_info()

Player Information
def get_player_info():
    return {
        "id": "cc9ddc91-2e0d-4565-af30-a39748f2344b",  # Unique player ID (GUID)
        "name": "Swamp Prawns"                           # Display name in game
    }
Important: Your player ID must be unique per player. Use a GUID generator to create unique IDs for multiple players.

2. get_actions(state: GameState)

Called once per unit turn. Analyze the game state and return action(s):

Basic Implementation - Always Move Up
from game import Action, is_empty

def get_actions(state):
    actions = []
    
    # Get your unit
    unit = state.unit
    
    # Try to move up
    if unit.y > 0 and is_empty(unit.x, unit.y - 1, state):
        actions.append(Action("Move", "Up"))
    else:
        # Fallback: try right
        actions.append(Action("Move", "Right"))
    
    return actions

3. game_end()

Called when the game finishes. Use for cleanup or logging:

Game End Handler
def game_end():
    # Cleanup resources, log statistics, etc.
    print("Game ended!")
    # No return value needed

Return Format

Your get_actions() must return a list of Action objects. When returned, they are automatically serialized to JSON:

Return Format Example
# Python return
actions = [Action("Move", "Up")]

# Auto-serialized to JSON sent to EvG:
[{"actionType": "Move", "direction": "Up"}]

Strategy Examples

Strategy 1: Simple Random Walker

Random Movement Strategy
import random
from game import Action, is_empty

def get_actions(state):
    directions = ["Up", "Down", "Left", "Right"]
    random.shuffle(directions)
    
    for direction in directions:
        x, y = state.unit.x, state.unit.y
        
        if direction == "Up":
            y -= 1
        elif direction == "Down":
            y += 1
        elif direction == "Left":
            x -= 1
        elif direction == "Right":
            x += 1
        
        # Check bounds and emptiness (derive size from floor_map — map dimensions vary per match)
        if 0 <= x < len(state.floor_map) and \
           0 <= y < len(state.floor_map[x]) and \
           is_empty(x, y, state):
            return [Action("Move", direction)]
    
    # No valid move found, stay still (return empty list)
    return []

Strategy 2: Chase Nearest Enemy

Chase Strategy Using Distance Maps
from game import Action

def get_actions(state):
    unit = state.unit
    
    # Find nearest foe
    nearest_foe = None
    min_distance = float('inf')
    
    for foe in state.foes:
        if foe.health > 0:  # Only consider alive enemies
            distance = unit.get_distance(foe.x, foe.y, state)
            if distance is not None and distance < min_distance:
                min_distance = distance
                nearest_foe = foe
    
    if nearest_foe is None:
        return []
    
    # Move toward foe
    if nearest_foe.x < unit.x:
        return [Action("Move", "Left")]
    elif nearest_foe.x > unit.x:
        return [Action("Move", "Right")]
    elif nearest_foe.y < unit.y:
        return [Action("Move", "Up")]
    elif nearest_foe.y > unit.y:
        return [Action("Move", "Down")]
    else:
        # We're on the same tile, attack!
        return [Action("Attack", "Up")]  # Direction varies by position

Strategy 3: Balanced Offense/Defense

Smart Combat Strategy
from game import Action, is_empty

def get_actions(state):
    unit = state.unit
    
    # If health is low, try to heal by moving away
    if unit.health <= 3:
        for direction in ["Up", "Down", "Left", "Right"]:
            x, y = unit.x, unit.y
            if direction == "Up":
                y -= 1
            elif direction == "Down":
                y += 1
            elif direction == "Left":
                x -= 1
            elif direction == "Right":
                x += 1
            
            if is_empty(x, y, state):
                return [Action("Move", direction)]
    
    # Check for adjacent enemies to attack
    for foe in state.foes:
        if foe.health <= 0:
            continue
        
        # Adjacent horizontally?
        if foe.y == unit.y and abs(foe.x - unit.x) == 1:
            direction = "Left" if foe.x < unit.x else "Right"
            return [Action("Attack", direction)]
        
        # Adjacent vertically?
        if foe.x == unit.x and abs(foe.y - unit.y) == 1:
            direction = "Up" if foe.y < unit.y else "Down"
            return [Action("Attack", direction)]
    
    # No adjacent enemies, move toward nearest foe
    nearest_foe = min(
        [f for f in state.foes if f.health > 0],
        key=lambda f: unit.get_distance(f.x, f.y, state) or float('inf'),
        default=None
    )
    
    if nearest_foe:
        if nearest_foe.x < unit.x:
            if is_empty(unit.x - 1, unit.y, state):
                return [Action("Move", "Left")]
        elif nearest_foe.x > unit.x:
            if is_empty(unit.x + 1, unit.y, state):
                return [Action("Move", "Right")]
        elif nearest_foe.y < unit.y:
            if is_empty(unit.x, unit.y - 1, state):
                return [Action("Move", "Up")]
        elif nearest_foe.y > unit.y:
            if is_empty(unit.x, unit.y + 1, state):
                return [Action("Move", "Down")]
    
    return []

Network Requirements

  • Outbound: Your bot must reach EvG server on startup (for registration)
  • Inbound: EvG must reach your bot on the configured port during games
  • Timeout: Your get_actions() must complete within 1 second
  • Response Size: Keep JSON responses small (typically <500 bytes)
⚠️ Important: If your Python bot is behind a NAT or Docker container, set PLAYER_HOST to an address that the EvG server can actually reach. Container-to-container networking requires proper host configuration.

Performance Considerations

Response Time Budget

  • EvG allows 1 second per action decision
  • Network latency + processing must fit in this window
  • Tornado server is non-blocking, so multiple requests won't queue

Optimization Tips

  • Cache distance maps: Unit objects cache their distance maps automatically
  • Avoid nested loops: Use min()/max() with generator expressions
  • Lazy evaluation: Only compute distances for alive enemies
  • Profile your code: Use Python's cProfile to find bottlenecks

Large Map Optimization

Fast Nearest Enemy Search
def get_nearest_alive_enemy(unit, foes, state):
    """Find nearest living enemy efficiently"""
    alive_foes = [f for f in foes if f.health > 0]
    
    if not alive_foes:
        return None
    
    # Only compute distances for alive enemies
    return min(
        alive_foes,
        key=lambda f: unit.get_distance(f.x, f.y, state) or float('inf')
    )

Advanced: Tornado Server Details

The main.py uses the Tornado web framework. Key aspects:

Request Handling Flow

How Requests Are Processed
MainHandler receives POST
  ↓
Extract JSON payload (game state)
  ↓
Call player.get_actions(GameState(payload))
  ↓
Serialize Action list to JSON
  ↓
Return JSON response (200 OK)
  ↓
If exception: return 500 with error message

File Monitoring

main.py spawns a monitor thread that watches player.py for changes:

  • Detects file writes every 1 second (poll_interval = 0.1)
  • Auto-reloads module using importlib.reload()
  • No server restart needed—changes take effect immediately
  • Useful during development for rapid iteration
